## 1. Мета роботи
Здобути практичні навички впровадження функціональності реального часу (real-time), створення розширених UI-компонентів, оптимізації продуктивності та розгортання React-застосунку на хостинг-платформі.

## 2. Хід роботи та результати

1. **Real-time (Socket.io):** Налаштовано підключення до WebSocket-сервера. Реалізовано компонент `NotificationBell` для відображення живих сповіщень. Створено глобальні хуки `useSocketConnection` та `useSocketEvent`.
2. **UI-компоненти:** Використано `@headlessui/react` для створення доступних модальних вікон (`Modal`, `ConfirmDialog`), які підтримують керування з клавіатури та керування фокусом.
3. **Інтерактивність:** Додано графік активності за допомогою `recharts`. Реалізовано "Дошку завдань" із функцією drag-and-drop через сучасну бібліотеку `@dnd-kit/core`.
4. **Оптимізація (Lazy Loading):** Впроваджено розбиття коду (code splitting) за маршрутами. Сторінки імпортуються динамічно через `React.lazy()` та обгорнуті в `<Suspense>` з компонентом завантаження.
5. **PWA та SEO:** Налаштовано `vite-plugin-pwa` для генерації Service Worker та маніфесту (кешування `NetworkFirst` для API). Додано метатеги (Open Graph, theme-color) у `index.html`.

## 3. Відповіді на контрольні запитання

1. **Поясніть різницю між WebSocket та HTTP.**
   HTTP працює за принципом "запит-відповідь": клієнт просить — сервер віддає. З'єднання після цього закривається. WebSocket створює постійне двостороннє з'єднання, через яке сервер може ініціювати відправку даних клієнту в будь-який момент (сповіщення, чати).

2. **Як правильно керувати життєвим циклом з'єднання Socket.io в React?**
   З'єднання створюється одне на весь додаток (в `Layout`), щоб не було дублікатів при переходах між сторінками. При розмонтуванні компонента вкрай важливо викликати `socket.off(event, handler)`, щоб зняти підписку на подію, інакше виникне витік пам'яті і повідомлення будуть дублюватися.

3. **Що таке портали React і як вони використовуються для модальних вікон?**
   `createPortal` дозволяє відрендерити компонент (модальне вікно) поза його поточним батьківським DOM-вузлом (наприклад, прямо в `<body>`). Це вирішує проблеми з `z-index` та `overflow: hidden`, які можуть обрізати вікно. Доступне модальне вікно має захоплювати фокус усередині себе (focus trap) і закриватися на клавішу `Escape`.

4. **Порівняйте бібліотеки для перетягування елементів у React.**
   Старий стандарт `react-dnd` складно налаштовувати і він погано працює на мобільних. Ми використали `dnd-kit` — він модульний, легковаговий, чудово працює на сенсорних екранах і, що дуже важливо, має вбудовану доступність (елементи можна перетягувати за допомогою клавіатури, датчик `KeyboardSensor`).

5. **Поясніть концепцію розбиття коду (Code Splitting).**
   Замість завантаження всього коду сайту в одному величезному `bundle.js`, код розбивається на шматки (chunks). З `React.lazy()` код певної сторінки завантажується з сервера лише тоді, коли користувач на неї переходить. `Suspense` вказує React, що показувати (наприклад, спіннер), поки файл вантажиться.

6. **Що таке Service Worker і як він забезпечує офлайн-функціональність у PWA?**
   Це JavaScript-файл, який працює у фоні (як проксі між браузером і мережею). Він може перехоплювати запити. Стратегія `CacheFirst` бере файл з кешу (добре для картинок). `NetworkFirst` спочатку йде в мережу, а при помилці — в кеш (для API). `StaleWhileRevalidate` миттєво віддає кеш, але у фоні оновлює його з мережі.

7. **Які метрики продуктивності важливі для вебзастосунків?**
   Core Web Vitals: LCP (час відмальовування найбільшого елемента), INP (затримка між дією користувача та реакцією інтерфейсу, прийшла на заміну FID), CLS (візуальна стабільність — наскільки стрибають елементи під час завантаження). Вимірюються в Lighthouse.

8. **Порівняйте Vercel та Netlify. Навіщо SPA потрібне правило перезапису?**
   Обидві платформи розгортають React-додатки безпосередньо з GitHub. Оскільки SPA має лише один файл `index.html`, прямий перехід за посиланням `/users` видасть помилку 404 на сервері. Правило перезапису (rewrites) змушує сервер завжди віддавати `index.html`, а роутинг вже підхоплює сам React на клієнті.

9. **Що таке CI/CD і які переваги дає автоматизація розгортання?**
   CI (безперервна інтеграція) автоматично перевіряє код (тести, лінтери) при кожному пуші. CD (безперервне розгортання) автоматично виливає код на сервер, якщо CI пройдено успішно. Це економить час, виключає людський фактор при деплої та не дає зламаному коду потрапити до кінцевого користувача.

10. **Як забезпечити SEO для односторінкових застосунків?**
    Додати метатеги (`<title>`, `<meta name="description">`), Open Graph теги для соцмереж. Оскільки SPA спочатку віддає порожній HTML, пошуковикам буває важко його індексувати. Якщо SEO критично важливе, використовують SSR (відмальовування на сервері) за допомогою фреймворків на кшталт Next.js.
