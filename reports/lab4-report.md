## 1. Мета роботи
Здобути практичні навички створення сучасного React-проєкту з використанням TypeScript, налаштування інструментів розробки (ESLint, Prettier) та побудови базової архітектури клієнтської частини застосунку з використанням Tailwind CSS для стилізації.

## 2. Хід роботи та результати

1. **Ініціалізація проєкту:** Створено новий застосунок `booking-client` за допомогою Vite із шаблоном `react-ts`. 
2. **Налаштування інструментів:** Встановлено та налаштовано Tailwind CSS 4. Замінено стандартний лінтер oxlint на повноцінний ESLint та додано Prettier для автоматичного форматування коду.
3. **Маршрутизація:** Налаштовано `React Router 8`. Створено базовий макет (`Layout`) із шапкою (`Header`) та підвалом (`Footer`), а також налаштовано переходи між сторінками (`HomePage`, `AboutPage`, `NotFoundPage`).
4. **Взаємодія з сервером (API):** Налаштовано екземпляр Axios (`src/services/api.ts`) із використанням interceptors для автоматичного додавання JWT-токена та перехоплення помилок авторизації (401).
5. **UI-компоненти та теми:** Створено базові компоненти (`Button`, `Input`). Реалізовано кастомний хук `useTheme` для перемикання між світлою та темною темами через додавання класу `dark` до тегу `<html>`. Налаштовано Error Boundary для відловлювання помилок рендеру.

## 3. Відповіді на контрольні запитання

1. **Які переваги має Vite порівняно зі збирачами на основі повного бандлінгу (Webpack)?**
   Vite використовує нативні ES-модулі браузера, що дозволяє миттєво запускати сервер розробки без попереднього збирання всього коду. Оновлення модулів (HMR) працює надшвидко, бо при зміні файлу оновлюється лише він, а не весь бандл.

2. **Що таке інтерфейси TypeScript та як вони використовуються для типізації пропсів?**
   Інтерфейси (`interface`) описують структуру об'єкта. У React вони використовуються для чіткого визначення того, які властивості (props) має отримати компонент і яких вони типів (наприклад, `interface ButtonProps`), що допомагає уникати помилок ще до запуску коду.

3. **Поясніть концепцію utility-first CSS та переваги Tailwind CSS. Що змінилося у версії 4?**
   Utility-first CSS передбачає використання готових класів-утиліт (наприклад, `flex`, `p-4`, `text-center`) безпосередньо в HTML/JSX замість написання власних CSS-правил. У Tailwind 4 налаштування теми відбувається прямо в CSS-файлі через директиву `@theme`, а `tailwind.config.js` та PostCSS більше не потрібні.

4. **Як працюють interceptors в Axios? Наведіть приклади.**
   Interceptors (перехоплювачі) дозволяють виконувати код перед відправкою запиту або перед обробкою відповіді. У проєкті `request interceptor` додає токен `Authorization: Bearer` до кожного запиту, а `response interceptor` ловить помилку 401 (Неавторизовано) і перекидає користувача на сторінку входу.

5. **Що таке `Outlet` у React Router?**
   `Outlet` — це компонент-заповнювач, який вказує батьківському маршруту, де саме відмальовувати дочірні компоненти. У проєкті він стоїть всередині `Layout`, щоб шапка і підвал залишалися на місці, а контент сторінки між ними динамічно змінювався.

6. **Поясніть різницю між ESLint та Prettier. Як уникнути конфліктів?**
   ESLint аналізує код на наявність логічних помилок та порушень практик написання, а Prettier лише форматує його зовнішній вигляд (відступи, лапки). Щоб вони не конфліктували, використовують плагін `eslint-config-prettier`, який вимикає всі правила ESLint, що стосуються стилю форматування.

7. **Змінні середовища: чому .env не додають у репозиторій і чому VITE_ не для секретів?**
   Файл `.env` не пушать у репозиторій з міркувань безпеки (щоб не "злити" паролі чи ключі від БД). Змінні з префіксом `VITE_` вшиваються у фінальний JS-код клієнта, тому вони доступні для перегляду будь-якому відвідувачу сайту через інструменти розробника в браузері. Зберігати там паролі небезпечно.

8. **Яких принципів слід дотримуватися при створенні UI-компонентів?**
   Принцип єдиної відповідальності (компонент виконує одне завдання), максимальне використання пропсів для гнучкості (наприклад, `variant="danger"` для кнопки), відсутність "жорстко" зашитої бізнес-логіки та використання TypeScript для валідації.

9. **Адаптивний дизайн та як Tailwind його спрощує?**
   Це здатність інтерфейсу підлаштовуватися під розміри екрана (мобільний, планшет, ПК). Tailwind спрощує це за допомогою префіксів-модифікаторів, наприклад, клас `md:grid-cols-3` застосує 3 колонки лише на екранах середнього розміру і більше, а за замовчуванням буде 1 колонка.

10. **Як організувати структуру папок у React-проєкті?**
    Найпопулярніші підходи: групування за типом файлів (окремо `components`, `pages`, `hooks`, `services`) або "Feature-Sliced Design" (групування за фічами, де кожна фіча містить свої компоненти та логіку). У проєкті використано перший варіант.
